# CLAUDE.md

## Purpose

This repository is the working knowledge base / Second Brain for Kasim Aslam and Pareto Talent.

Use it as persistent project context when answering questions, researching, drafting communications, planning projects, or making recommendations related to Kasim, Pareto Talent, and the projects documented here.

The repository contains both source material and synthesized knowledge. Do not treat every document as equally authoritative.

---

## Repository structure

- `00_Start-Here/` — orientation, templates, naming conventions, and operating rules.
- `01_Context/` — core context about Kasim, Pareto Talent, priorities, positioning, team, story, and voice.
- `02_Intake/` — incoming/source material. `raw/` contains source material; `processed/` contains cleaned or synthesized versions.
- `03_Projects/` — project-specific context and working documents.
- `04_Knowledge/` — consolidated knowledge, research, playbooks, FAQs, and frameworks.
- `05_Decisions/` — decisions and decision history.
- `06_Communications/` — communication assets, scripts, emails, and published material.
- `07_Archive/` — historical material that should generally receive lower priority unless specifically requested.

---

## Context priority

When sources conflict, use this general hierarchy:

1. Explicit instructions in the current conversation.
2. Current project-specific documents in `03_Projects/`.
3. Current decisions in `05_Decisions/`.
4. Core context in `01_Context/`.
5. Consolidated knowledge in `04_Knowledge/`.
6. Processed source material in `02_Intake/processed/`.
7. Raw source material in `02_Intake/raw/`.
8. Archived material in `07_Archive/`.

When a newer source clearly supersedes an older source, prefer the newer source and note the conflict when it matters.

---

## Source discipline

- Do not invent facts that are not supported by the repository or the current conversation.
- Distinguish verified facts, documented statements, interpretations, assumptions, and recommendations.
- When information is uncertain or incomplete, say so rather than filling gaps with guesses.
- Preserve the distinction between what Kasim/Pareto Talent actually said or did and an interpretation of what it means.
- For external/current facts, verify against an appropriate current source when the task requires up-to-date information.
- Do not silently convert assumptions into facts.
- When quoting or paraphrasing source material, preserve its meaning and context.

---

## Working with raw vs. processed material

`02_Intake/raw/` contains source material and should be treated as evidence.

`02_Intake/processed/` contains cleaned or transformed material and may be easier to use, but it should not automatically override the underlying raw source.

When accuracy matters, trace important claims back to the raw source.

## Projects

Before working on a project:

1. Check the relevant folder in `03_Projects/`.
2. Read the project's `overview.md` or equivalent orientation document.
3. Check relevant decisions in `05_Decisions/`.
4. Check related knowledge in `04_Knowledge/`.
5. Use raw intake material when source-level detail is required.

Do not assume that information from one project applies to another.

---

## Decisions

Treat `05_Decisions/decision-log.md` as the record of documented decisions.

Do not reverse or reinterpret a documented decision without making the conflict explicit.

If a new request appears to contradict an existing decision, surface the conflict instead of silently ignoring it.

---

## Updating the Second Brain

When asked to add or update knowledge:

- Put information in the most appropriate existing folder.
- Prefer updating an existing canonical document over creating unnecessary duplicates.
- Preserve source provenance when practical.
- Keep raw source material unchanged.
- Use the repository's naming conventions from `00_Start-Here/naming-and-rules.md`.
- Avoid creating duplicate facts in multiple places unless there is a clear reason.
- When a new decision is made, consider whether `05_Decisions/decision-log.md` should be updated.

---

## Confidentiality and sensitive information

Treat repository contents as private project information.

Do not expose sensitive information unnecessarily.

When producing external-facing material, include only information appropriate for the intended audience.

---

## Default behavior

When asked a question about Kasim, Pareto Talent, or a documented project:

1. Identify which repository sections are relevant.
2. Read the relevant source/context before answering.
3. Separate facts from interpretation.
4. Use the most current applicable information.
5. Cite or identify the relevant repository source when useful.
6. If the repository does not contain enough information, say what is missing rather than guessing.

The goal is not merely to retrieve documents. The goal is to use this repository as a coherent, evolving Second Brain while preserving source accuracy and context.
